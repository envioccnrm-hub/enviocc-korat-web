# ระบบติดตามการปรับปรุงแก้ไขหลังการประเมินมาตรฐานโรงพยาบาล
สำนักงานสาธารณสุขจังหวัดนครราชสีมา — ชุดไฟล์สำหรับรันบนเครื่อง (Local Host)

## 1. เปิดดูบนเครื่องตัวเอง

```bash
cd "โฟลเดอร์ของโปรเจกต์นี้"
python3 -m http.server 8080
```

แล้วเปิดเบราว์เซอร์ไปที่ **http://localhost:8080/index.html**

> ⚠️ ห้ามดับเบิลคลิกเปิดไฟล์ตรง ๆ (`file://...`) เพราะเบราว์เซอร์จะบล็อกการเรียก API
> ต้องเปิดผ่าน `http://localhost` เท่านั้น

### การแยกสิทธิ์ (บังคับที่ Apps Script ไม่ใช่ที่เบราว์เซอร์)

ล็อกอินสำเร็จ → Apps Script ออก **token** ที่มีลายเซ็น (HMAC-SHA256) กลับมา เก็บไว้ใน `localStorage` แล้วแนบไปกับ **ทุกคำสั่ง** หลังจากนั้น

token เก็บแค่ `role` + `ชื่อหน่วยงาน` + `เวลาหมดอายุ` แก้เนื้อในไม่ได้เพราะลายเซ็นจะไม่ตรง และหมดอายุเองใน **12 ชั่วโมง** (`TOKEN_TTL_HOURS` ใน `Code.gs`)

| คำสั่ง | ใครเรียกได้ |
|---|---|
| `login`, `getDropdowns` | เปิดสาธารณะ (หน้าล็อกอินต้องใช้ก่อนมี token) |
| `getMasterData`, `getDocuments` | ผู้ที่ล็อกอินแล้ว |
| `getSubmissions`, `getRegistry` | ล็อกอินแล้ว — **ถ้าไม่ใช่ สสจ. ระบบบังคับกรองเป็นหน่วยงานของตัวเองเสมอ** ต่อให้หน้าเว็บส่งชื่อหน่วยงานอื่นมาก็ไม่มีผล |
| `getStats` | ล็อกอินแล้ว — คืนตัวเลขรวมทั้งจังหวัดให้ รพ. เอาไปเทียบกับตัวเองได้ แต่ไม่มีชื่อผู้ส่ง เบอร์โทร หรือลิงก์หลักฐาน |
| `submitReport` | ล็อกอินแล้ว — ถ้าไม่ใช่ สสจ. จะส่งในนามหน่วยงานอื่นไม่ได้ |
| `getUsers`, `saveUser`, `deleteUser`, `updateStatus` | **เฉพาะ สสจ. เท่านั้น** |

- `getUsers` **ไม่ส่งรหัสผ่านกลับออกมาแล้ว** ส่งแค่ `hasPassword` ว่ามีตั้งไว้หรือยัง
- แก้ไขผู้ใช้แล้วเว้นช่องรหัสผ่านว่าง = คงรหัสเดิม โดย `saveUser` อ่านของเดิมจากชีตเอง หน้าเว็บจึงไม่ต้องรู้รหัสผ่านของใครเลย
- token หมดอายุหรือสิทธิ์ไม่พอ → Apps Script ตอบ `code: AUTH_REQUIRED` / `FORBIDDEN` → หน้าเว็บล้างข้อมูลแล้วเด้งกลับหน้าล็อกอินอัตโนมัติ

> **ต้อง Deploy Apps Script ใหม่ถึงจะมีผล** และหลัง deploy ทุกคนที่ล็อกอินค้างไว้ต้องล็อกอินใหม่หนึ่งรอบ (ของเดิมไม่มี token)

### การเด้งหน้าตามสิทธิ์

**การเด้งหน้า:**

- ล็อกอินสำเร็จ → ระบบอ่านคอลัมน์ **E (สิทธิ์)** ในชีต `Login รายชื่อผู้ใช้งาน`
  - `admin` → เด้งไป `admin.html`
  - อย่างอื่น → เด้งไป `hospital.html`
- เข้าหน้าผิดสิทธิ์ (เช่น รพ. พิมพ์ URL `admin.html` เอง) → ระบบเด้งกลับหน้าของตัวเองอัตโนมัติ
- ยังไม่ล็อกอิน → เด้งกลับ `index.html`

## 3. ติดตั้งหลังบ้าน (สำคัญ — ต้องทำถึงจะได้ข้อมูลจริง)

1. เปิด Google Sheet ที่ใช้งาน → เมนู **ส่วนขยาย → Apps Script**
2. ลบโค้ดเดิมทั้งหมด แล้ววางเนื้อหาจากไฟล์ `Code.gs` ในโฟลเดอร์นี้ทับลงไป
3. กด **Deploy → New deployment → เลือก Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** ← ถ้าตั้งผิดตรงนี้ หน้าเว็บจะดึงข้อมูลไม่ได้
4. คัดลอกลิงก์ที่ลงท้ายด้วย `/exec`
5. เอามาวางใน `assets/config.js` บรรทัด `API_URL`
6. รีเฟรชหน้าเว็บ → แถบสีส้ม "โหมดตัวอย่าง" จะหายไป = ต่อสำเร็จ

> ทุกครั้งที่แก้ `Code.gs` ต้อง **Deploy ใหม่** (หรือ Manage deployments → Edit → New version) ไม่งั้นของเดิมจะยังทำงานอยู่

### ตรวจระบบเมื่อมีอะไรไม่ทำงาน

ใน `Code.gs` มีฟังก์ชัน **`ตรวจระบบ`** ไว้ไล่หาสาเหตุ

1. เปิด Apps Script → เลือกฟังก์ชัน **`ตรวจระบบ`** จากแถบด้านบน → กด **Run**
2. ดูผลที่ **Execution log**

ตรวจให้ 3 อย่าง:
- **โฟลเดอร์ Drive** ทั้งสองสายงาน — เปิดได้ไหม และ **เขียนไฟล์ได้จริงไหม** (สร้างไฟล์ทดสอบแล้วลบทิ้งให้เอง)
- **ชีตติดตามงาน** — มีคอลัมน์ ชื่อโรงพยาบาล / สถานะ / ลิงก์หลักฐาน / ระดับผลการประเมิน ครบไหม ถ้าขาดจะบอกว่าขาดตัวไหนและไล่หัวคอลัมน์ที่มีอยู่จริงมาให้ดู
- **การเข้ารหัสภาษาไทยใน token** — ถ้าชื่อเพี้ยนเป็น `????` แปลว่าโค้ดที่ deploy ยังเป็นรุ่นเก่า

> **การกด Run ครั้งแรกจะขึ้นหน้าต่างขออนุญาตสิทธิ์ Google Drive ให้กดอนุญาต**
> นี่เป็นวิธีที่แน่นอนที่สุดในการเปิดสิทธิ์ Drive เพราะกด Deploy เฉย ๆ บางครั้งไม่ขอสิทธิ์ใหม่ให้
> ถ้าสิทธิ์ Drive ไม่เคยถูกอนุญาต `DriveApp.getFolderById()` จะล้มเหลวทั้งที่ ID ถูกและโฟลเดอร์แชร์ไว้แล้ว

### เช็กว่า deploy รุ่นไหนอยู่

เปิด `<API_URL>?action=ping` จะได้ `version` กลับมา เทียบกับ `CODE_VERSION` ที่หัวไฟล์ `Code.gs`
ถ้าไม่ตรง แปลว่ายังไม่ได้ Deploy รุ่นล่าสุด

### การแนบไฟล์ PDF ขึ้น Google Drive

หน้าโรงพยาบาลแนบหลักฐานได้ 2 ทาง — **อัปโหลดไฟล์ PDF โดยตรง** หรือ **วางลิงก์ Google Drive** (จะใช้ทั้งสองอย่างก็ได้ แต่ต้องมีอย่างน้อยหนึ่งอย่าง)

ไฟล์ที่อัปโหลดจะถูกเก็บใน Drive ของเจ้าของ Apps Script โดยแยกโฟลเดอร์ย่อยตามชื่อหน่วยงาน แล้วเขียนลิงก์ลงคอลัมน์หลักฐานในชีตให้อัตโนมัติ

- เก็บแยกคนละโฟลเดอร์ตามสายงาน ตั้งค่าไว้ที่หัวไฟล์ `Code.gs`:
  | สายงาน | ค่าคงที่ | โฟลเดอร์ |
  |---|---|---|
  | Green & Clean | `UPLOAD_FOLDER_GREEN_ID` | รวมไฟล์ PDF งานแก้ไข Green & Clean |
  | อาชีวอนามัยฯ | `UPLOAD_FOLDER_OCC_ID` | รวมไฟล์ PDF งานแก้ไข อาชีวอนามัยฯ |
- เปลี่ยนโฟลเดอร์ได้โดยเอา ID จากท้าย URL `drive.google.com/drive/folders/<ID>` มาวางแทน
- ถ้าเว้น ID ว่างไว้ ระบบจะหา/สร้างโฟลเดอร์ตามชื่อให้เองอัตโนมัติ
- **บัญชีที่เป็นเจ้าของ Apps Script ต้องมีสิทธิ์แก้ไขโฟลเดอร์นั้น** ไม่งั้นอัปโหลดไม่ได้
- ขนาดไฟล์: ไฟล์ละไม่เกิน **15 MB** รวมต่อหนึ่งรายงานไม่เกิน **25 MB**
  (ตั้งเผื่อไว้เพราะ base64 ทำให้ข้อมูลบวมขึ้นราว 1.34 เท่า ขณะที่ Apps Script รับ POST ได้ 50 MB)
- ถ้าจะเปลี่ยนเพดานขนาด ต้องแก้ให้ตรงกันทั้ง `MAX_UPLOAD_MB` ใน `Code.gs` และ `MAX_FILE_MB` ใน `assets/hospital.js`

> ครั้งแรกที่ Deploy หลังเพิ่มความสามารถนี้ Apps Script จะ **ขอสิทธิ์เข้าถึง Google Drive เพิ่ม** ต้องกดอนุญาต ไม่งั้นการอัปโหลดจะขึ้น error
>
> ถ้าอัปโหลดไฟล์ไม่สำเร็จ ระบบจะ **ไม่บันทึกแถวลงชีต** เพื่อไม่ให้เกิดรายการที่ไม่มีหลักฐานแนบ — ผู้ใช้กดส่งใหม่ได้เลย

### ชีตที่ระบบใช้ (โค้ดอ่าน/เขียนตามหัวคอลัมน์เดิม ไม่มีการเพิ่มหรือย้ายคอลัมน์)

| ชื่อแท็บ | ระบบใช้ทำอะไร |
|---|---|
| `Login รายชื่อผู้ใช้งาน` | A อำเภอ · B ประเภทหน่วยงาน · C ชื่อโรงพยาบาล · D รหัสผ่าน/รหัสโรงพยาบาล · E สิทธิ์ (Admin/Hospital) · F ชื่อผู้บันทึก |
| `Master_Data_Green` | A หมวด · B ข้อ · C ประเภทโรงพยาบาลที่ใช้เกณฑ์นี้ (คอลัมน์ A เว้นว่างได้ ระบบยึดหมวดล่าสุด) |
| `Master_Data_Occ` | โครงสร้างเดียวกัน แต่เป็นงานอาชีวอนามัยฯ |
| `ติดตามงาน Green & Clean Hospital` | ปุ่ม "บันทึกและส่งรายงาน" เขียนลงคอลัมน์ A–N · หน้า Admin อ่านกลับมาแสดง · ปุ่ม "บันทึกผลการตรวจ" เขียนทับ L (สถานะ) กับ M (หมายเหตุ) |
| `ติดตามงาน อาชีวอนามัยและเวชกรรมสิ่งแวดล้อม` | เหมือนกัน |
| `ทะเบียนรายชื่อโรงพยาบาล` | ใช้เติม "ปีที่ประเมิน" ให้อัตโนมัติ และแสดงผลการรับรองล่าสุด |
| แท็บที่มีคอลัมน์ `FileUrl` | คลังคู่มือ/เอกสาร → แสดงในแท็บ "คู่มือและเอกสาร" (ระบบหาแท็บให้เอง ไม่ต้องตั้งชื่อ) |

### การกรองเกณฑ์ตามประเภทโรงพยาบาล

แต่ละชีตเขียนชื่อประเภทไม่เหมือนกัน (`รพ.สต.` / `โรงพยาบาลส่งเสริมสุขภาพส่วนตำบล` / `รพ.ศูนย์/ รพ.ทั่วไป/ รพ.ชุมชน/ รพ.นอก สป.สธ.`)
ระบบจึงแปลงทุกคำให้เป็น **รหัสกลาง** ก่อนเทียบ แล้วค่อยกรอง

| รหัส | ครอบคลุมคำว่า |
|---|---|
| `CEN` | รพ.ศูนย์, โรงพยาบาลศูนย์, รพศ. |
| `GEN` | รพ.ทั่วไป, โรงพยาบาลทั่วไป, รพท. |
| `COM` | รพ.ชุมชน, โรงพยาบาลชุมชน, รพช. |
| `SUB` | รพ.สต., โรงพยาบาลส่งเสริมสุขภาพส่วนตำบล |
| `OUT` | รพ.นอก สป.สธ., เอกชน |
| `LOC` | อปท., ท้องถิ่น |
| `PHO` | สสจ. (= สิทธิ์ Admin) |

ผู้ใช้**ไม่ต้องเลือกประเภทเอง** ระบบล็อกให้จากข้อมูลตอนล็อกอิน (ช่องจะมีรูปกุญแจ)

ผลการกรองกับข้อมูลจริงในชีตตอนนี้:

| ประเภทที่ล็อกอิน | Green | อาชีวฯ |
|---|---|---|
| รพ.ศูนย์ / รพ.ทั่วไป | 9 หมวด / 50 ข้อ | ยังไม่มีเกณฑ์ในชีต |
| รพ.ชุมชน | 9 หมวด / 50 ข้อ | 5 องค์ประกอบ / 42 ข้อ |
| รพ.สต. | 7 หมวด / 66 ข้อ | ยังไม่มีเกณฑ์ในชีต |
| อปท. | ยังไม่มีเกณฑ์ในชีต | ยังไม่มีเกณฑ์ในชีต |

ช่องที่เขียนว่า "ยังไม่มีเกณฑ์ในชีต" หน้าเว็บจะขึ้นข้อความแจ้งให้ติดต่อ สสจ.
**เติมแถวใน Master_Data ให้ครอบคลุมประเภทนั้นเมื่อไหร่ รายการจะขึ้นเองทันที ไม่ต้องแก้โค้ด**

## 3.5 แดชบอร์ดวิเคราะห์ (แต่ละสิทธิ์เห็นคนละมุม)

ทุกตัวเลข **คำนวณสดจากแถวจริงในชีต** ตอนเปิดหน้า — ไม่มีค่าคงที่ฝังไว้ และ **ไม่มีการเขียนอะไรกลับลงชีต**
(การเขียนชีตยังมีแค่ 3 จุดเดิม: ส่งรายงาน · บันทึกผลการตรวจ · จัดการผู้ใช้)

### หน้า สสจ. (`admin.html` → ปุ่ม "แดชบอร์ดวิเคราะห์")

ขอบเขตของกราฟ = เมนูซ้าย (ทั้งหมด / Green / อาชีวฯ) + ตัวกรองอำเภอ/ประเภท/ปี/คำค้น
(ไม่รวมตัวกรองสถานะ เพราะกราฟต้องเห็นทุกสถานะจึงคำนวณสัดส่วนได้)

| ส่วนที่แสดง | คำนวณจาก |
|---|---|
| รายการส่งงานทั้งหมด | จำนวนแถว + นับหน่วยงานไม่ซ้ำ |
| อัตราการรับรองผล | แถวสถานะ "รับรองผลเรียบร้อยแล้ว" ÷ แถวทั้งหมด |
| ค้างดำเนินการ | แถวที่ยังไม่รับรอง แยกเป็น รอตรวจ / ตรวจแล้ว / ต้องแก้ไข |
| ความครอบคลุมของหน่วยงาน | หน่วยงานที่ส่งแล้ว ÷ หน่วยงานในชีต `ทะเบียนรายชื่อโรงพยาบาล` (ถ้าไม่มีทะเบียน ใช้ชีต Login แทน) |
| อันดับหมวด/องค์ประกอบที่ถูกส่งแก้ไขมากที่สุด | คอลัมน์ "หมวดที่ต้องการแก้ไข" — 1 แถวเลือกหลายหมวด นับให้ครบทุกหมวด |
| สัดส่วนระดับผลการประเมิน | คอลัมน์ "ระดับผลการประเมิน" |
| สถิติการส่งแก้ไขรายข้อ (10 ข้อแรก) | คอลัมน์ "ข้อที่ต้องการแก้ไข" |
| แนวโน้ม 12 เดือน | คอลัมน์ "วันที่ส่ง" |
| สรุปรายอำเภอ / รายประเภทหน่วยงาน | join อำเภอจากชีต Login ให้อัตโนมัติ |
| หน่วยงานที่ส่งมากที่สุด / ค้างตรวจมากที่สุด | ใช้เป็นคิวงานตรวจของ สสจ. |

### หน้าโรงพยาบาล (`hospital.html` → แท็บ "ภาพรวมของฉัน" เป็นแท็บแรก)

เห็นเฉพาะข้อมูลของหน่วยงานตัวเอง (กรองด้วยชื่อโรงพยาบาลที่ล็อกอิน)

| ส่วนที่แสดง | คำนวณจาก |
|---|---|
| ส่งแล้ว / รอตรวจ / ต้องแก้ไข / รับรองแล้ว | รายงานของหน่วยงานนี้ในชีตติดตามงาน |
| ความครอบคลุมรายงานแก้ไข (แยก Green / อาชีวฯ) | ข้อที่ส่งแก้ไขแล้ว ÷ จำนวนข้อทั้งหมดตามเกณฑ์ของ**ประเภทหน่วยงานตัวเอง** ใน Master_Data |
| สิ่งที่ต้องดำเนินการต่อ | แถวสถานะ "ต้องแก้ไขเพิ่มเติม" พร้อมข้อเสนอแนะจาก สสจ. แล้วตามด้วยแถวที่ยังรอตรวจ |
| หมวดที่ส่งแก้ไขมากที่สุด | คอลัมน์ "หมวดที่ต้องการแก้ไข" ของหน่วยงานนี้ |
| เทียบกับภาพรวมจังหวัด | อัตราการรับรองของตัวเอง เทียบกับ `getStats` ทั้งจังหวัด |
| ผลการรับรองล่าสุด | ชีต `ทะเบียนรายชื่อโรงพยาบาล` (ปี / ระดับ / สถานะ / หมดอายุ) |
| แนวโน้ม 12 เดือน | วันที่ส่งของหน่วยงานนี้ |

> ⚠️ แดชบอร์ดจะขึ้นตัวเลขจริงก็ต่อเมื่อ **Deploy `Code.gs` ตัวใหม่แล้ว** (ดูข้อ 3)
> ตอนนี้ URL ที่อยู่ใน `config.js` ยังเป็นหลังบ้านตัวเก่าที่ตอบกลับเป็นข้อความ ไม่ใช่ JSON → ระบบจะตกไปโหมดตัวอย่าง

## 4. โหมดตัวอย่าง (Demo)

ถ้าต่อ Google Sheet ไม่ได้ ระบบจะโชว์ข้อมูลจำลองพร้อมแถบสีส้มด้านล่างจอ เพื่อให้ดูหน้าตาเว็บได้ก่อน

- รหัสผ่านในโหมดตัวอย่างคือ **1234** (ทุกโรงพยาบาล)
- เลือก **สสจ.นครราชสีมา** = เข้าหน้า Admin / เลือกโรงพยาบาลอื่น = เข้าหน้าโรงพยาบาล
- ปิดโหมดนี้ได้โดยตั้ง `ALLOW_DEMO_FALLBACK: false` ใน `assets/config.js`

## 5. สิ่งที่แก้จากไฟล์เดิม

| เดิม | ตอนนี้ |
|---|---|
| หน้า Admin เป็น React build ที่ต่อ Sheet ไม่ได้ (URL เป็น `.../s/.../exec`) | เขียนใหม่เป็น HTML ธรรมดา ดึงข้อมูลจริง แก้ไขต่อได้ |
| URL Apps Script มี 2 อันไม่ตรงกันในไฟล์เดียว | รวมไว้ที่ `config.js` ที่เดียว |
| ส่งฟอร์มด้วย `mode:'no-cors'` → ขึ้น "สำเร็จ" แม้บันทึกไม่ลง | อ่านคำตอบจริงจากเซิร์ฟเวอร์ ถ้าพลาดจะแจ้ง error |
| ระบบเลือกหมวด/ข้อ ซ้อนกัน 2 ชุด เขียนทับกัน | เหลือชุดเดียว แยก state ของแต่ละแท็บ |
| ตอนส่งงานไม่ได้บันทึกชื่อโรงพยาบาล/อำเภอ | บันทึกครบ Admin จึงกรองรายจังหวัดได้ |
| ไม่มีทางอัปเดตสถานะกลับเข้าชีต | มีปุ่ม "ตรวจงาน/แก้ไข" เขียนสถานะ + ความเห็นกลับเข้าชีต |
| แถบสถานะ/ตารางประวัติเป็นข้อมูล hard-code | วาดจากข้อมูลจริงของโรงพยาบาลที่ล็อกอิน |

## 6. เว็บที่ขึ้นออนไลน์แล้ว

**https://envioccnrm-hub.github.io/enviocc-korat-web/**

เสิร์ฟด้วย GitHub Pages จาก branch `main` โฟลเดอร์ root ของ repo
`envioccnrm-hub/enviocc-korat-web` — **push ขึ้น main เมื่อไหร่ เว็บอัปเดตเองภายในไม่กี่นาที**

ไฟล์เว็บทั้งหมดต้องอยู่ที่ **root ของ repo** (ไม่ใช่ในโฟลเดอร์ย่อย) เพราะ GitHub Pages
มองหา `index.html` ที่ root ถ้าย้ายไปไว้ในโฟลเดอร์ย่อยเมื่อไหร่ ลิงก์หลักจะขึ้น 404 ทันที

> เว็บกับหลังบ้านอัปเดต **คนละทาง** — push แล้วได้แค่หน้าเว็บ
> ส่วน `Code.gs` ต้องเอาไปวางใน Apps Script แล้วกด Deploy เองทุกครั้ง (ดูข้อ 3)

ชุดไฟล์นี้เป็น static ล้วน จะย้ายไป Vercel / Cloud Run ก็ได้ ไม่ต้องแก้อะไร
นอกจาก `API_URL` ใน `assets/config.js`
